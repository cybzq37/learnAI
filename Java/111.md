# Java IO

> Java IO 的核心学习路线：
>
> **IO 是什么 → 输入输出 → 字节流/字符流 → 文件读写 → 缓冲/转换等增强 → 节点流/处理流 → flush/close/资源管理 → 特殊 IO → 实战 → NIO → BIO/NIO/AIO → 面试总结**

可以分为文件IO 网络IO
---

# 一、IO 基础

## 1. 什么是 IO

IO（Input / Output）表示程序与外部设备之间进行数据交换的过程。

程序运行过程中，数据通常来自：

* 文件
* 网络
* 键盘
* 内存
* 数据库
* 其他程序

Java 通过 IO API 对这些数据进行读取和写入。

简单来说：

```text
外部数据
   ↓
Input
   ↓
Java 程序
   ↓
Output
   ↓
外部设备
```

### Input

Input 表示**输入**，也就是数据从外部进入程序。

例如：

```text
文件 → 程序
网络 → 程序
键盘 → 程序
```

### Output

Output 表示**输出**，也就是数据从程序输出到外部。

例如：

```text
程序 → 文件
程序 → 网络
程序 → 控制台
```

---

## 2. Java IO 的两种主要分类方式

Java IO 可以从两个角度理解。

### 按数据单位分类

分为：

* 字节流
* 字符流

```text
IO
├── 字节流
│   ├── InputStream
│   └── OutputStream
│
└── 字符流
    ├── Reader
    └── Writer
```

### 按方向分类

分为：

* 输入流
* 输出流

因此组合起来就是：

```text
                输入              输出
              Input             Output

字节流    InputStream        OutputStream

字符流    Reader             Writer
```

这是理解 Java IO 类体系最重要的一张图。

---

## 3. Java IO 整体体系

传统 Java IO 主要围绕以下几个核心抽象展开：

```text
InputStream
OutputStream

Reader
Writer
```

在此基础上又产生了大量具体实现和增强类。

例如：

```text
文件
 ↓
FileInputStream / FileOutputStream
 ↓
BufferedInputStream / BufferedOutputStream
```

或者：

```text
文件
 ↓
FileInputStream
 ↓
InputStreamReader
 ↓
BufferedReader
```

所以学习 IO 时，不应该把这些类当成互相独立的 API，而应该理解成：

> **不同类型的流可以进行组合，在基础 IO 能力上不断增加新的功能。**

# 二、传统 IO 基础

# 1. InputStream / OutputStream

## 1.1 InputStream

`InputStream` 是 Java 字节输入流体系的顶层抽象。

常见方法：

```java
int read()
```

读取一个字节。

```java
int read(byte[] b)
```

一次读取多个字节。

```java
int read(byte[] b, int off, int len)
```

从指定位置开始读取指定长度的数据。

```java
void close()
```

关闭流。

---

## 1.2 OutputStream

`OutputStream` 是 Java 字节输出流体系的顶层抽象。

常见方法：

```java
void write(int b)
```

写入一个字节。

```java
void write(byte[] b)
```

写入一个字节数组。

```java
void write(byte[] b, int off, int len)
```

写入字节数组的一部分。

```java
void flush()
```

刷新缓冲区。

```java
void close()
```

关闭流。

---

# 2. Reader / Writer

字符流体系对应：

```text
Reader
Writer
```

## 2.1 Reader

`Reader` 是字符输入流的顶层抽象。

常见方法：

```java
int read()
```

读取一个字符。

```java
int read(char[] cbuf)
```

读取多个字符。

```java
int read(char[] cbuf, int off, int len)
```

读取指定范围的字符。

---

## 2.2 Writer

`Writer` 是字符输出流的顶层抽象。

常见方法：

```java
void write(int c)
void write(char[] cbuf)
void write(char[] cbuf, int off, int len)
void write(String str)
void flush()
void close()
```

---

# 3. FileInputStream / FileOutputStream

文件操作是最典型的字节流应用。

## 3.1 FileInputStream

用于从文件中读取字节。

```java
FileInputStream fis = new FileInputStream("test.txt");

int data;

while ((data = fis.read()) != -1) {
    System.out.println(data);
}

fis.close();
```

其中：

```java
read()
```

返回 `int`。

当读取到文件末尾时返回：

```java
-1
```

---

## 3.2 批量读取

一个字节一个字节读取效率较低。

可以使用字节数组进行批量读取：

```java
byte[] buffer = new byte[1024];

int len;

while ((len = fis.read(buffer)) != -1) {
    System.out.println(new String(buffer, 0, len));
}
```

这里的 `len` 非常重要。

`len` 表示：

> **本次实际读取了多少字节。**

不能直接把整个 `buffer` 都写出去，因为最后一次读取时，buffer 可能没有被完全填满。

---

## 3.3 FileOutputStream

用于向文件中写入字节。

```java
FileOutputStream fos = new FileOutputStream("test.txt");

fos.write("hello".getBytes());

fos.close();
```

---

## 3.4 追加模式

默认情况下：

```java
new FileOutputStream("test.txt")
```

会覆盖原文件内容。

如果希望追加：

```java
new FileOutputStream("test.txt", true)
```

第二个参数：

```java
true
```

表示追加写入。

---

# 4. FileReader / FileWriter

如果处理的是文本数据，可以使用字符流。

## 4.1 FileReader

```java
FileReader reader = new FileReader("test.txt");

int c;

while ((c = reader.read()) != -1) {
    System.out.print((char) c);
}

reader.close();
```

---

## 4.2 FileWriter

```java
FileWriter writer = new FileWriter("test.txt");

writer.write("Hello Java");

writer.close();
```

---

# 5. 字节流 vs 字符流

这是 Java IO 中非常重要的基础概念。

| 对比       | 字节流                        | 字符流             |
| -------- | -------------------------- | --------------- |
| 基础类      | InputStream / OutputStream | Reader / Writer |
| 操作单位     | 字节                         | 字符              |
| 适合       | 二进制数据                      | 文本数据            |
| 常见文件     | 图片、视频、音频、压缩包               | txt、csv、源码等     |
| 是否涉及字符编码 | 通常不直接处理                    | 通常需要考虑          |

可以简单理解：

```text
图片 / 视频 / 音频 / 压缩包
        ↓
      字节流


文本
        ↓
      字符流
```

但是要注意：

> 字符流本质上仍然需要通过字符编码将字符和字节进行转换。

# 三、IO 流的功能增强

基础流能够完成 IO，但是功能比较简单。

例如：

```text
FileInputStream
```

只能负责从文件读取字节。

如果希望：

* 提高读取效率
* 按字符读取
* 按行读取
* 指定字符编码
* 读写基本数据类型
* 读写对象

就需要在基础流上进行增强。

主要增强方式包括：

```text
缓冲流
转换流
Data 流
Object 流
Print 流
```

---

# 1. 缓冲流

常见缓冲流：

```text
BufferedInputStream
BufferedOutputStream

BufferedReader
BufferedWriter
```

---

## 1.1 为什么需要缓冲流

如果每次读一个字节都直接访问文件：

```text
程序
 ↓
文件
 ↓
程序
 ↓
文件
 ↓
程序
 ↓
文件
```

频繁进行底层 IO 操作，效率比较低。

缓冲流会在内存中建立缓冲区：

```text
程序
 ↓
缓冲区
 ↓
文件
```

可以减少底层 IO 操作次数。

---

## 1.2 BufferedInputStream

```java
InputStream in =
        new BufferedInputStream(
                new FileInputStream("test.txt")
        );
```

---

## 1.3 BufferedOutputStream

```java
OutputStream out =
        new BufferedOutputStream(
                new FileOutputStream("test.txt")
        );
```

---

## 1.4 BufferedReader

`BufferedReader` 是字符缓冲输入流。

最大的特点之一是：

```java
readLine()
```

可以一次读取一整行。

```java
BufferedReader reader =
        new BufferedReader(
                new FileReader("test.txt")
        );

String line;

while ((line = reader.readLine()) != null) {
    System.out.println(line);
}

reader.close();
```

---

## 1.5 BufferedWriter

```java
BufferedWriter writer =
        new BufferedWriter(
                new FileWriter("test.txt")
        );

writer.write("Hello");
writer.newLine();
writer.write("Java");

writer.close();
```

其中：

```java
newLine()
```

用于写入换行符。

---

# 2. 转换流

转换流：

```text
InputStreamReader
OutputStreamWriter
```

主要作用：

> **在字节流和字符流之间进行转换。**

---

## 2.1 为什么需要转换流

文件底层本质上保存的是：

```text
字节
```

但是 Java 程序处理文本时希望使用：

```text
字符
```

所以需要：

```text
字节
 ↓
字符
```

或者：

```text
字符
 ↓
字节
```

转换流就是负责完成这件事情。

---

## 2.2 InputStreamReader

```text
InputStream
    ↓
InputStreamReader
    ↓
Reader
```

示例：

```java
InputStream in =
        new FileInputStream("test.txt");

Reader reader =
        new InputStreamReader(in, "UTF-8");
```

更推荐明确指定字符编码：

```java
Reader reader =
        new InputStreamReader(
                new FileInputStream("test.txt"),
                "UTF-8"
        );
```

---

## 2.3 OutputStreamWriter

```text
Writer
 ↓
OutputStreamWriter
 ↓
OutputStream
```

示例：

```java
Writer writer =
        new OutputStreamWriter(
                new FileOutputStream("test.txt"),
                "UTF-8"
        );
```

---

## 2.4 转换流 + 缓冲流

实际开发中经常组合：

```text
FileInputStream
       ↓
InputStreamReader
       ↓
BufferedReader
```

代码：

```java
BufferedReader reader =
        new BufferedReader(
                new InputStreamReader(
                        new FileInputStream("test.txt"),
                        "UTF-8"
                )
        );
```

这段代码可以理解成：

```text
文件
 ↓
字节读取
 ↓
UTF-8 解码
 ↓
字符读取
 ↓
缓冲
 ↓
程序
```

## 3.1 DataOutputStream

例如：


```java

in.readDouble();
in.readBoolean();
```

不能随意改变顺序。

# 四、IO 的设计思想

# 1. 节点流

节点流直接连接数据源或数据目的地。

例如：

```text
文件
 ↓
FileInputStream
```

这里 `FileInputStream` 直接连接文件。

常见节点流：

```text
FileInputStream
FileOutputStream

FileReader
FileWriter
```

---

# 2. 处理流

处理流不直接连接数据源，而是在其他流的基础上增加功能。

例如：

```text
FileInputStream
       ↓
BufferedInputStream
```

其中：

```text
FileInputStream
```

是节点流。

```text
BufferedInputStream
```

是处理流。

---

# 3. 装饰器模式

Java IO 大量使用了类似装饰器模式的设计思想。

例如：

```java
new BufferedReader(
    new InputStreamReader(
        new FileInputStream("test.txt")
    )
)
```

可以拆成：

```text
FileInputStream
        ↓
InputStreamReader
        ↓
BufferedReader
```

每一层负责不同的事情。

### 第一层

```text
FileInputStream
```

负责：

> 从文件读取字节。

### 第二层

```text
InputStreamReader
```

负责：

> 将字节转换成字符。

### 第三层

```text
BufferedReader
```

负责：

> 提供缓冲以及按行读取等能力。

因此最终：

```text
BufferedReader
```

具备了多层能力。

---

# 4. 流的组合

可以把 Java IO 理解成：

```text
数据源
  ↓
节点流
  ↓
功能增强
  ↓
功能增强
  ↓
程序
```

例如：

```text
文件
 ↓
FileInputStream
 ↓
InputStreamReader
 ↓
BufferedReader
 ↓
按行读取
```

这也是理解 Java IO API 的关键。

不要把下面这些类理解成孤立的：

```text
FileInputStream
InputStreamReader
BufferedReader
```

而应该理解为：

> **它们可以通过组合形成一条完整的数据处理链。**

# 五、IO 使用机制

# 1. 字符编码

文本数据在文件中最终仍然以字节形式保存。

因此存在：

```text
字符
 ↕
字节
```

之间的转换。

这个转换依赖：

```text
字符编码
```

常见编码：

```text
UTF-8
GBK
UTF-16
```

实际开发中建议明确指定字符编码，例如：

```java
new InputStreamReader(
    new FileInputStream("test.txt"),
    "UTF-8"
);
```

以及：

```java
new OutputStreamWriter(
    new FileOutputStream("test.txt"),
    "UTF-8"
);
```

---

# 2. flush()

`flush()` 的作用是：

> **将缓冲区中的数据尽可能写入目标位置。**

例如：

```java
BufferedWriter writer =
        new BufferedWriter(
                new FileWriter("test.txt")
        );

writer.write("Hello");

writer.flush();
```

调用 `flush()` 后，缓冲区中的数据会被刷新。

---

# 3. close()

`close()` 的作用不仅仅是释放资源。

通常还会：

```text
刷新缓冲区
+
关闭底层资源
```

例如：

```java
writer.close();
```

一般情况下关闭流后不能继续使用该流。

---

# 4. flush vs close

可以这样理解：

| 方法      | 作用            |
| ------- | ------------- |
| flush() | 刷新缓冲区，但不代表关闭流 |
| close() | 关闭流，并通常会先执行刷新 |

因此：

```text
flush
```

解决的是：

> 数据什么时候真正往下层发送。

而：

```text
close
```

解决的是：

> 资源什么时候释放。

---

# 5. try-with-resources

传统写法：

```java
FileInputStream in = null;

try {
    in = new FileInputStream("test.txt");

    // 使用流

} finally {
    if (in != null) {
        in.close();
    }
}
```

代码比较繁琐。

Java 提供了：

```java
try-with-resources
```

例如：

```java
try (FileInputStream in =
         new FileInputStream("test.txt")) {

    // 使用流

}
```

执行结束后会自动关闭资源。

---

## 5.1 AutoCloseable

能够使用 try-with-resources 的资源需要实现：

```java
AutoCloseable
```

很多 IO 流都满足这个条件。

因此：

```java
try (资源) {
    
}
```

可以自动进行资源关闭。

Java IO 中很多操作都可能发生异常，因此大量 IO API 会抛出：

```java

```

常见异常：

```text

UnsupportedEncodingException
```

其中：

# 六、特殊 IO 工具

# 1. ByteArrayInputStream / ByteArrayOutputStream

普通文件流的数据源是文件。

而 ByteArray 流的数据源是：

```text
内存中的 byte[]
```

例如：

```java
byte[] data = "Hello".getBytes();

ByteArrayInputStream in =
        new ByteArrayInputStream(data);
```

输出：

```java
ByteArrayOutputStream out =
        new ByteArrayOutputStream();
```

它们适合：

> 在内存中模拟 IO 操作。

---

# 2. CharArrayReader / CharArrayWriter

与 ByteArray 流类似，只不过操作的是：

```text
char[]
```

例如：

```text
CharArrayReader
CharArrayWriter
```

数据直接存在内存中。

---

# 3. RandomAccessFile

`RandomAccessFile` 和普通顺序流最大的区别是：

> **可以随机访问文件中的任意位置。**

普通流：

```text
开始
 ↓
 ↓
 ↓
 ↓
结束
```

通常按照顺序读取。

而 `RandomAccessFile` 可以通过文件指针定位：

```text
文件
--------------------------------
0    10    20    30    40    50
                ↑
              seek()
```

例如：

```java
RandomAccessFile raf =
        new RandomAccessFile("test.txt", "rw");

raf.seek(10);

int data = raf.read();

raf.close();
```

`seek()` 可以移动文件指针。

常见模式：

```text
r
rw
```

# 七、IO 实战

# 1. 文本读取

最简单：

```java
FileReader reader =

while ((c = reader.read()) != -1) {

```

```java
BufferedReader
```

```java
try (BufferedReader reader =
         new BufferedReader(

    String line;

    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}
```

---

# 2. UTF-8 文本读取

更推荐显式指定编码：

```java
try (BufferedReader reader =
         new BufferedReader(
             new InputStreamReader(
                 new FileInputStream("test.txt"),
                 "UTF-8"
             ))) {

    String line;

    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}
```

完整的数据流：

```text
文件
 ↓
FileInputStream
 ↓
InputStreamReader
 ↓
UTF-8 解码
 ↓
BufferedReader
 ↓
String
```

# 3. 文件复制

文件复制是 Java IO 中非常经典的练习。

核心思路：

```text
源文件
 ↓
InputStream
 ↓
byte[]
 ↓
OutputStream
 ↓
目标文件
```

示例：

```java
try (
    FileInputStream in =
        new FileInputStream("source.txt");

    FileOutputStream out =
        new FileOutputStream("target.txt")
) {

    byte[] buffer = new byte[1024];

    int len;

    while ((len = in.read(buffer)) != -1) {
        out.write(buffer, 0, len);
    }
}
```

这里最容易出错的地方是：

```java
out.write(buffer, 0, len);
```

而不是：

```java
out.write(buffer);
```

因为：

```java
len
```

表示本次真正读取的数据长度。

最后一次读取时：

```text
buffer.length = 1024
len = 300
```

如果直接：

```java
out.write(buffer);
```

就可能把之前残留在 buffer 中的数据也写进去。

所以应该：

```java
out.write(buffer, 0, len);
```

只写入本次实际读取的数据。

基本模式：

```java
     ↓
```

不要为了复制二进制文件而使用字符流。

# 八、Java NIO

传统 IO 主要围绕：

```text
Stream
```

展开。

Java NIO 则引入了：

```text
Buffer
Channel
Selector
Path
Files
```

等核心概念。

# 1. IO vs NIO

传统 IO：

```text
InputStream
OutputStream
Reader
Writer
```

核心思想：

```text
Stream
```

NIO：

```text
Buffer
Channel
Selector
```

核心思想发生了变化。

可以简单理解：

```text
传统 IO
数据 → Stream → 程序

NIO
数据 ↔ Buffer ↔ Channel ↔ 程序
```

# 2. Buffer

Buffer 是 NIO 的核心组件之一。

常见 Buffer：

```text
ByteBuffer
CharBuffer
IntBuffer
LongBuffer
FloatBuffer
DoubleBuffer
ShortBuffer
```

最常见的是：

```java
ByteBuffer
```

---

## 2.1 Buffer 的核心属性

Buffer 中最重要的概念：

```text
capacity
position
limit
```

可以理解为：

```text
capacity
┌─────────────────────────────┐
│                             │
│       Buffer 空间            │
│                             │
└─────────────────────────────┘
          ↑
       capacity

position：当前读写位置

limit：当前操作边界
```

---

## 2.2 flip()

写入 Buffer 后，如果要读取：

```java
buffer.flip();
```

`flip()` 的核心作用：

> 将 Buffer 从写模式切换到读模式。

典型流程：

```text
写入
 ↓
flip()
 ↓
读取
```

---

## 2.3 clear()

读取完成后，可以：

```java
buffer.clear();
```

准备下一轮写入。

# 3. Channel

Channel 是 NIO 的另一个核心概念。

常见 Channel：

```text
FileChannel
SocketChannel
ServerSocketChannel
DatagramChannel
```

传统 IO：

```text
Stream
```

NIO：

```text
Channel
```

Channel 通常和 Buffer 配合使用。

例如：

```text
FileChannel
      ↕
  ByteBuffer
```

---

# 4. Buffer + Channel

典型读取流程：

```text
文件
 ↓
FileChannel
 ↓
ByteBuffer
 ↓
程序
```

示意：

```java
ByteBuffer buffer =
        ByteBuffer.allocate(1024);

while (channel.read(buffer) != -1) {

    buffer.flip();

    while (buffer.hasRemaining()) {
        // 读取 buffer 中的数据
    }

    buffer.clear();
}
```

核心流程：

```text
allocate
 ↓
channel.read(buffer)
 ↓
flip
 ↓
读取
 ↓
clear
 ↓
下一轮
```

# 5. Selector

Selector 是 NIO 非阻塞 IO 中非常重要的组件。

它可以让一个线程监听多个 Channel。

传统阻塞模型：

```text
线程1 → 客户端1
线程2 → 客户端2
线程3 → 客户端3
...
```

连接很多时，需要大量线程。

Selector 模型：

```text
             ┌→ Channel 1
             │
Selector ────┼→ Channel 2
             │
             ├→ Channel 3
             │
             └→ Channel 4
```

一个线程可以通过 Selector 关注多个 Channel 的事件。

例如：

```text
连接事件
可读事件
可写事件
```

NIO.2 中引入：

```java
Path
```

用于表示文件系统路径。

例如：

```java
Path path = Paths.get("test.txt");
```

相较于传统：

```java
File
```

`Path` 提供了更加现代化的文件系统 API。

# 7. Files

`Files` 提供了大量文件操作方法。

例如：

```java
Files.exists(path);
```

判断文件是否存在。

```java
Files.createFile(path);
```

创建文件。

```java
Files.delete(path);
```

删除文件。

```java
Files.copy(source, target);
```

复制文件。

```java
Files.move(source, target);
```

移动文件。

```java
Files.readAllBytes(path);
```

读取文件。

```java
Files.write(path, data);
```

写入文件。

因此：

```text

 +

```

是现代 Java 文件操作的重要 API。

# 九、网络 IO 模型

网络 IO 是在 IO 基础之上进一步讨论：

> **程序如何处理大量网络连接。**

主要涉及：

```text
BIO
NIO
AIO
```

---

# 1. BIO

BIO：

```text
Blocking IO
```

即阻塞 IO。

典型模型：

```text
客户端1 → 线程1
客户端2 → 线程2
客户端3 → 线程3
```

一个连接通常对应一个处理线程。

---

## 1.1 BIO 特点

优点：

* 编程简单
* 容易理解
* 适合连接数量较少的场景

缺点：

* 线程资源消耗较大
* 大量连接时容易产生大量线程
* 阻塞等待时线程无法处理其他任务

---

# 2. NIO 网络模型

NIO 可以使用：

```text
Channel
Buffer
Selector
```

进行非阻塞网络 IO。

典型模型：

```text
             ┌→ Channel 1
             │
             ├→ Channel 2
             │
Selector ────┼→ Channel 3
             │
             └→ Channel 4
```

一个线程可以监听多个连接。

---

## 2.1 NIO 特点

优点：

* 非阻塞
* 一个线程可以管理多个连接
* 更适合高并发场景

缺点：

* 编程复杂度更高
* 需要理解 Selector、Channel、Buffer 等概念

---

# 3. AIO

AIO：

```text
Asynchronous IO
```

即异步 IO。

核心思想：

> 发起 IO 操作后，不需要一直等待结果，而是在 IO 完成后通过回调等机制通知程序。

可以理解成：

```text
程序
 ↓
发起 IO
 ↓
继续执行其他任务
 ↓
IO 完成
 ↓
通知程序
```

---

# 4. BIO / NIO / AIO 对比

| 模型  | 核心特点 | 典型思想                  |
| --- | ---- | --------------------- |
| BIO | 阻塞   | 一个连接通常对应一个线程          |
| NIO | 非阻塞  | Selector 管理多个 Channel |
| AIO | 异步   | IO 完成后通知程序            |

可以记成：

```text
BIO
阻塞等待

NIO
主动轮询 / 事件驱动

AIO
完成后通知
```

---

# 5. Reactor

在网络编程中，还经常会遇到：

```text
Reactor
```

Reactor 是一种事件驱动的网络 IO 设计思想。

核心过程：

```text
事件发生
   ↓
事件分发
   ↓
对应 Handler
   ↓
处理事件
```

Selector 是 Java NIO 中实现事件驱动网络模型的重要基础。

# 十、Java IO 高频面试总结

# 1. 字节流和字符流有什么区别？

字节流以：

```text
byte
```

为基本处理单位。

字符流以：

```text
char
```

为基本处理单位。

通常：

```text
二进制文件 → 字节流

文本文件 → 字符流
```

---

# 2. 为什么 BufferedReader 比 FileReader 更方便？

`BufferedReader` 在字符流基础上增加了缓冲能力，并提供：

```java
readLine()
```

可以方便地按行读取文本。

结构：

```text
FileReader
   ↓
BufferedReader
```

---

# 3. 为什么需要 InputStreamReader？

因为：

```text
InputStream
```

处理的是字节。

而：

```text
Reader
```

处理的是字符。

所以需要：

```text
InputStream
      ↓
InputStreamReader
      ↓
Reader
```

完成：

```text
字节 → 字符
```

同时可以指定字符编码。

---

# 4. flush() 和 close() 有什么区别？

`flush()`：

```text
刷新缓冲区
```

`close()`：

```text
关闭资源
+
通常先刷新缓冲区
```

所以：

```text
flush ≠ close
```

---

# 5. 为什么文件复制使用 byte[]？

因为文件可能是：

```text
图片
视频
音频
压缩包
PDF
```

这些都属于二进制数据。

使用字节流可以保证：

```text
原始字节
   ↓
原样复制
   ↓
目标文件
```

---

# 6. 文件复制为什么要 write(buffer, 0, len)？

因为：

```java
len
```

表示本次实际读取的数据长度。

例如：

```text
buffer 大小：1024
实际读取：300
```

那么：

```java
write(buffer)
```

会尝试写整个 buffer。

正确方式：

```java
write(buffer, 0, 300)
```

即：

```java
write(buffer, 0, len)
```

---

# 7. Java IO 为什么大量使用装饰器模式？

因为可以把不同功能进行组合。

例如：

```text
FileInputStream
      ↓
InputStreamReader
      ↓
BufferedReader
```

每个类只负责一部分功能。

最终通过组合形成完整能力。

这体现了：

> **面向对象中的组合思想。**

---

# 8. DataInputStream 和 DataOutputStream 为什么要求顺序一致？

因为写入的数据是按照特定顺序组织的。

例如：

```java
writeInt();
writeDouble();
writeBoolean();
```

读取必须：

```java
readInt();
readDouble();
readBoolean();
```

否则读取时无法正确解析数据。

---

# 9. Serializable、serialVersionUID、transient 分别是什么？

### Serializable

表示类支持 Java 默认序列化。

### serialVersionUID

用于控制序列化版本兼容性。

### transient

表示该字段不参与默认序列化。

---

# 10. BIO、NIO、AIO 的区别

```text
BIO
Blocking IO
阻塞

NIO
Non-blocking IO
非阻塞

AIO
Asynchronous IO
异步
```

核心区别：

```text
BIO：
等结果

NIO：
关注事件

AIO：
等完成通知
```
