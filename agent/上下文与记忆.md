上下文的七大组成要素：

- System Instructions — 系统指令，定义角色和行为边界
- User Prompt — 用户的当前请求
- Conversation History — 对话历史
- Long-Term Memory — 跨会话的持久记忆
- Retrieved Information (RAG) — 实时检索的外部知识
- Available Tools — 可用工具的定义和 schema
- Output Format — 输出格式要求

每一项都在争夺上下文窗口这块有限的空间。上下文工程的核心挑战，就是在这七个维度之间做出最优分配。Agent 的失败，本质上是上下文的失败，而不是模型的失败。

### 记忆系统

要让 Agent「记得住做过什么」，需要一套分级记忆。这也是「核心组件」里记忆模块的落地。Agent 中的记忆，通常围绕两个维度展开：**短期/长期**（时间尺度）与**情景/语义/经验**（内容类型）。

**短期记忆（Short-term）**：当前对话的上下文。会话变长时，Agent 会对历史消息做摘要/压缩，只保留重要信息重新放入 context。

**长期记忆（Long-term）**：解决"当前会话结束、下次能否记住"的问题。信息不能只放 context，需要**持久化存储**，可分为事实记忆 / 情景记忆 / 经验记忆。

**短期记忆如何存储？**
短期记忆本质上是保存当前任务所需上下文与状态，而非永久保存所有历史。
- 存储在 Redis
- 若 Agent 执行时间很长，采用 数据库 + Redis 存储

注意：短期记忆 ≠ 把 message 一直保存。全部塞给 LLM 会出现上下文膨胀，因此通常要做 **Token 检测**，超过阈值就压缩/摘要，得到「Summary + 最近消息」再放入 Context。

最终的 Context 可能是：

```text
┌──────────────────────────┐
│ System Prompt            │
├──────────────────────────┤
│ Conversation Summary     │ ← 压缩后的历史
├──────────────────────────┤
│ Recent Messages          │ ← 最近 N 条
├──────────────────────────┤
│ Relevant Memories        │ ← 从长期记忆检索
├──────────────────────────┤
│ Current Agent State      │ ← 当前任务状态
└──────────────────────────┘
```

**短期记忆应该在何时转成长期记忆？**
- 当用户明确要求"立即记忆"
- 在任务结束后记忆
- 在 context 压缩时记忆

短期转长期的过程：

```text
短期记忆 Conversation / Working Memory
        ↓
   重要性判断
        ↓
   信息抽取
        ↓
去重 / 冲突检测
        ↓
结构化 & Embedding
        ↓
长期记忆 Semantic（语义、事实） / Episodic（情景） / Procedural（程序、经验）

分别对应：知道什么？发生过什么？以后怎么做？
```

**分级记忆体系（存储选型）：**

- **工作记忆**：记录会话消息，生命周期与单个会话绑定，会话结束后自动清理，采用内存存储，TTL 管理。
- **情景记忆**：长期存储具体的交互事件和学习经历，使用 SQLite + Qdrant。
- **语义记忆**：存储更抽象的知识、概念和规则，使用 Qdrant + Neo4j。
- **感知记忆**：专门处理图像、音频等多模态信息，支持跨模态检索，使用 SQLite + Qdrant。
